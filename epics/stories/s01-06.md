# S01-06: Map Layers Notebook (OSM, OpenSeaMap, WMS/WMTS, GeoTIFF)

> Status: Done | Epic: 01 | Last updated: 2026-05-02

## Description

Create `notebooks/06_map_layers.ipynb` that validates the tile sources (OSM, OpenSeaMap), tests loading a sample GeoTIFF as a georeferenced overlay, and tests adding a user-specified WMS layer — all in ipyleaflet or folium. Goal: confirm tile URLs work, understand any CORS or proxy requirements, and establish GeoTIFF display patterns.

## Tasks

1. Create `notebooks/06_map_layers.ipynb`
2. Build ipyleaflet or folium map centered on Kiel Bight (54.5°N, 10.5°E)
3. Add OSM TileLayer; verify at zoom levels 6, 10, 14
4. Add OpenSeaMap TileLayer over OSM; verify seamark symbols visible at zoom ≥ 10
5. Load a sample GeoTIFF (any publicly available raster, or a small test image): use `rasterio` to get bounds; add as ImageOverlay
6. Test adding a public WMS layer (e.g., BSH or DWD WMS for Baltic weather/ocean data)
7. Add GEBCO bathymetry WMS: call GetCapabilities on `https://wms.gebco.net/mapserv`, confirm `GEBCO_LATEST` layer, render as overlay
8. Add EMODnet Seabed Habitats WMS: call GetCapabilities on `https://ows.emodnet-seabedhabitats.eu/geoserver/emodnet_view/wms`, confirm `eusm_helcom_group` layer, render as overlay
9. Document any CORS issues encountered (will need server-side proxy in Phase 2)
10. Note tile URL templates and any rate limits in `ops/data-sources.md`

## Implementation Notes

- **Key files**: `notebooks/06_map_layers.ipynb`
- **Deviations**:
  - GEBCO WMS URL changed: `gebco.net/.../mapserv` → `https://wms.gebco.net/mapserv` (old returns 404)
  - EMODnet layer `eusm2022` no longer exists; service restructured to per-scale layers; using `eusm_helcom_group` (HELCOM Baltic, multi-scale group); `_full`-suffix layers blank at overview zoom
  - GeoTIFF overlay implemented as synthetic PNG data URI (no real file download needed for Phase 1 validation); rasterio/numpy workflow pattern established
  - CORS: tile servers and WMS both accessible directly from Python; browser CORS behavior may differ (Phase 2: server-side proxy for WMS)
