# S03-06: Go/No-Go Dashboard

> Status: Done | Epic: 03 | Last updated: 2026-05-03

## Description

A summary dashboard panel at the top of the sidebar showing a per-capability
status indicator (green/amber/red) and an overall Go/No-Go recommendation.
All thresholds configurable via constants; no backend call required — derived
from data already fetched by other panels.

## PRD References
FR-01 (planning dashboard)

## Thresholds (defaults, all configurable)

| Capability | Green | Amber | Red |
|---|---|---|---|
| Wind | ≤ 15 kt | ≤ 25 kt | > 25 kt |
| Gusts | ≤ 20 kt | ≤ 30 kt | > 30 kt |
| Wave height (Hs) | ≤ 0.4 m | ≤ 0.8 m | > 0.8 m |
| Cloud cover | ≤ 20% | ≤ 50% | > 50% |
| Solar elevation | ≥ 20° | ≥ 10° | < 10° |

Overall: **Go** if all green; **Caution** if any amber and no red; **No-Go** if any red.

## Acceptance Criteria

- [x] Dashboard card at top of sidebar with overall verdict (Go/Caution/No-Go)
- [x] Per-capability rows: icon + label + status dot (green/amber/red) + current value
- [x] Overall verdict derived from per-capability statuses; updates reactively as data loads
- [x] "Last refreshed" timestamp shown; manual refresh button (↻ in dashboard header; triggers `refreshSignal` in `GoNoGoContext` which panels subscribe to)
- [x] Capabilities with pending/failed data shown as "—" (grey dot); overall verdict held until all data loads
- [x] Thresholds editable via a settings modal; persisted to `localStorage`

## Implementation Notes

- `GoNoGoContext`: push model — panels push values via `update()` when their `useFetch` data arrives; `refreshSignal` counter triggers panel refetches when dashboard ↻ is clicked
- `GoNoDashboard`: overall verdict computed on every render from live statuses; `SettingsModal` uses controlled inputs (`value=` not `defaultValue`) so Reset Defaults visually updates fields
- WeatherPanel/WavePanel/SolarPanel: each subscribes to `refreshSignal` and calls its `refetch` when signal > 0 (skips initial mount)
- FR-16 AI synthesis: "AI assessment: coming soon" placeholder row

## Gate 4 (Raze) Fixes

Two findings resolved:
1. `defaultValue` (uncontrolled) in `SettingsModal` inputs meant Reset Defaults was visually broken — user saw no change. Fixed: `value=` (controlled). `draft` state now drives the input DOM.
2. No refresh button in dashboard panel — AC-4 explicitly requires it. Fixed: added `↻` button → `triggerRefresh()` → `refreshSignal` counter → panels refetch via subscribed `useEffect`.
