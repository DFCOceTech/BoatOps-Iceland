# S01-01: Weather Data Notebook (Open-Meteo + MeteoAlarm)

> Status: Done | Epic: 01 | Last updated: 2026-05-02

## Description

Create `notebooks/01_weather.ipynb` that validates the Open-Meteo API for wind, temperature, precipitation, and cloud cover data over a German Baltic Sea test AOI, and the MeteoAlarm API for weather advisories. Establish the query patterns and response shapes that will be used in the FastAPI service layer.

## Tasks

1. Create `notebooks/01_weather.ipynb`
2. Query Open-Meteo `/v1/forecast` for `wind_speed_10m`, `wind_direction_10m`, `temperature_2m`, `precipitation`, `cloudcover` for test bbox and 7-day window
3. Parse and inspect response shapes; document variable names, units, time resolution
4. Test m/s → knots conversion
5. Query MeteoAlarm for advisories; determine correct endpoint and parse response format
6. Produce simple plots: wind speed time series, cloud cover heatmap, advisory polygon on folium/ipyleaflet map
7. Document any API quirks or limitations in `ops/data-sources.md`

## Implementation Notes

- **Key files**: `notebooks/01_weather.ipynb`
- **Deviations**:
  - MeteoAlarm Atom feed has **no polygon geometry** — area described in plain text only. For map overlays, Phase 2 must use DWD WFS or EUMETNET GeoJSON API instead.
  - Open-Meteo returns single-point forecast (not gridded) for a given lat/lon. Adequate for Go/No-Go; multi-point grid deferred to Phase 2.
  - Wind direction can be exactly 360° (due north) — assertion must use `<= 360`, not `< 360`.
